# 产物断言消融实验（2026-09-08）

## 这份实验回答什么

`scripts/check-public-output.mjs` 有 67 处断言。`xiaorong-todo.md` 提出的问题是：**这些断言里哪些在真正防回归，哪些只是「我做了所以断言它在」。**

原提案要用读者侧数据（停留时长、Search Console 展现点击）来判断「读者价值」，但读者侧四项指标已于 2026-08-31 裁决为不再回填，度量不存在，那条路走不通。本次改用不依赖读者数据的方法：**变异测试**。逐项破坏功能，重新构建，看 `npm test` 是否变红。

## 方法

三个方向，共 27 次消融，每次都从干净快照还原源码后再变异：

- **A 删除式**：把断言直接盯着的标记拿掉。回答「功能消失时断言会不会响」。
- **B 掏空式**：保留标记字符串，只杀掉标记背后的行为。回答「断言是不是只在断言它在」。`src/scripts/site.js` 的 `initPage()` 是天然的接缝，注释掉一次调用即可保留全部 HTML 标记而让行为消失。
- **C 覆盖盲区**：只在断言没有检查的页面上移除功能。回答「断言的页面覆盖面够不够」。

判定标准是 `npm test` 的退出码。所有判为「漏掉」的条目都做了反证：确认变异真的进入了构建产物，产物真的退化了，而测试仍然是绿的。

结果：**27 次消融，12 次被抓到，15 次漏掉。**

## 方法学发现：本机缓存导致假绿

改动 `astro.config.mjs` 里 markdown 图片插件的两次消融，第一轮显示「漏掉」，实为 `node_modules/.astro` 内容缓存复用了旧的 markdown 渲染结果，只删 `.astro` 和 `dist` 不够。探针属性 `data-ablation-probe` 在不清缓存时出现 0 次，清掉后出现 25 次。全批清缓存重跑后，其中一条翻转为「抓到」。

本机 `npm test` 因此不是隔离的；CI 是全新 checkout 不受影响。改动 `astro.config.mjs` 的 markdown 配置后先 `rm -rf .astro node_modules/.astro dist`。

## 发现一：整个前端脚本失效不会被发现，而且是「危险失败」

这是本次最重的结论。

把 `BaseLayout.astro` 里的 `import "../scripts/site.js"` 整行注释掉，`npm test` 依然退出 0。

严重之处不在于「有些交互没了」，而在于失败方向。页面由一段独立的内联脚本给 `<html>` 加上 `js` 类，而打包后的样式里有这样一条规则：

```css
html.js [data-reveal]{opacity:0;transform:translateY(12px)}
```

解除透明依赖 `site.js` 的 `initReveal()` 给元素加 `revealed` 类。脚本一旦不执行，`js` 类照加，`opacity:0` 照生效，`revealed` 永远不会来。构建产物里确认：`revealed` 在全部打包 JS 中出现 0 次。

受影响的元素：

| 页面 | 永久不可见的 data-reveal 元素 |
| --- | --- |
| 首页 | 5 |
| 文章列表 | 4 |
| 分类页 | 1 |
| 合集页 | 1 |

也就是说，脚本挂掉时读者看到的是大面积空白，而不是一个「少了动画但内容还在」的降级页面。这属于危险失败而非安全失败，且约 60 条断言无一能察觉。

八次单项掏空（定时发布过滤、主题切换、滚动显现、代码复制、图片灯箱、阅读进度弧、目录高亮、分享按钮）**全部漏掉**，无一例外。所有针对交互功能的断言检查的都是标记字符串在不在，没有一条能证明行为还活着。

## 发现二：三条断言可以被无关的东西兜住

这三条是字面意义上的「我做了所以我断言它在」——它们盯的字符串可以由完全不相干的来源提供。

**归档页年份分组**。把 `class="year-block"` 全部改名后测试仍绿。原因是页面内联样式表里有 `.year-block { ... }` 这条 CSS 规则，`assertIncludes(archive, "year-block")` 命中的是样式文本。实测：改名后页面里带该 class 的元素为 0 个，而 `year-block` 字样仍出现 1 次。**任何用 class 名做断言、而该 class 又在同页样式里出现的检查，都有同样的问题。**

**正文图懒加载**。关掉 markdown 插件的 `loading ??= 'lazy'` 后测试仍绿。断言的写法是扫描整页 HTML 找 `<img loading="lazy">`，找不到就报「no article page has lazy-loaded body images」。但页脚的公众号二维码图在 `BaseLayout.astro:166` 硬编码了 `loading="lazy"` 且自带宽高。实测：正文 prose 区内的懒加载图降到 0，全站却仍有 14 张 lazy 图，全是这张页脚二维码。一个页脚装饰把正文的懒加载保障整个兜住了。

**检索页 Pagefind 初始化**。把 `new PagefindUI({` 换成一个不存在的构造函数后测试仍绿，因为同文件另一处 `window.PagefindUI` 让字符串继续存在。实测：真正的构造调用为 0 次，`PagefindUI` 字样仍有 1 次。

## 发现三：断言的页面覆盖面有洞

`check-public-output.mjs` 顶部的 `pages` 数组只含首页、文章列表、分类、合集、检索五个列表页。**文章详情页不在其中**，而文章页恰恰是流量意图最强的页面。

三次只针对文章页的移除全部漏掉：

- 主题切换按钮从文章页移除：首页仍有 1 个，文章页 0 个，测试绿。
- 页脚二维码从文章页移除：同上，测试绿。
- canonical 链接从文章页移除：首页仍有 1 个，文章页 0 个，测试绿。最后这条有直接 SEO 后果。

## 发现四：真正有牙的断言长什么样

12 条被抓到的消融里，大多数是「删掉标记 → 断言找不到标记」的直给型，它们确实能防住整块功能被误删，价值成立但上限有限。其中三条明显更强：

- **OG 图品牌弧位置**。这是全部断言里唯一做计算的一条：从模板里解析出 transform 的平移量和缩放比，算出弧的右边界，超过 1200px 画布就报错。把平移量从 810 改到 1100，它报出 `OG brand arc is clipped at right edge: 1488px > 1200px`。它约束的是几何后果，不是字符串在不在。
- **正文图宽高补齐**。关掉插件里的宽高赋值后，断言逐个检查每张懒加载图是否带 `width` 和 `height`，抓到了。它验证的是构建期真的算出了尺寸。
- **作者实体**。把结构化数据里的作者从 `site.author` 改回 `Azen`，首页和文章页两处都被抓到——正向断言 `"name":"ZENINEXU"` 和反向断言不含 `"name":"Azen"` 同时生效。这是 2026-08-06 事故后加的，防的是真实踩过的坑。

## 结论

这套断言的实际能力边界是：**它保护构建期产物的结构完整性，不保护任何运行时行为**。

- 防得住：页面没生成、结构化数据写错、封面尺寸缺失、OG 图裁切、作者实体漂移、整块 HTML 被误删。
- 防不住：前端脚本整体失效（且失败方向是内容不可见）、任何交互行为损坏、文章详情页上的任何退化、以及三条可被无关文本兜住的假断言。

`xiaorong-todo.md` 原本的判断是「不要削弱 `npm test`」。这个判断依然成立，本次没有发现任何一条该删的断言。但它同时假定这套断言已经足够扎实，而实测表明覆盖面比预期窄：**15/27 的变异逃逸率，说明补强比削弱重要得多。**

## 由此产生的整改项

以下五项已于 2026-09-08 全部完成（见 CHANGELOG 归档）：

1. 让滚动显现改为安全失败。要么把 `opacity:0` 的兜底交给 `@media (prefers-reduced-motion)` 之外的超时兜底，要么由脚本自己加 `js` 类而不是内联脚本加，这样脚本没跑时内容默认可见。这一条不改，任何一次 JS 打包事故都会让站点看起来是空的。
2. 断言里加一条「打包产物中存在 `revealed` 字样」或等价的脚本存活检查，让整个 `site.js` 失联能被发现。
3. 把 `pages` 数组扩展到包含至少一个文章详情页，或者对文章页复用同一组通用断言（页眉、页脚、主题切换、canonical）。
4. 修掉三条可被兜住的断言：年份分组改断言 `class="year-block"` 而不是 `year-block`；懒加载断言限定在正文 prose 区域内；Pagefind 断言改为检查真正的构造调用。
5. 在 `docs/maintenance.md` 记一句：改动 `astro.config.mjs` 的 markdown 配置后，本机验证必须先清 `node_modules/.astro`，否则 `npm test` 会给假绿。

## 未覆盖
