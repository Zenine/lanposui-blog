有开发者逆向了 Claude Code 的核心逻辑，发现它的心脏只是一段 `while(true)` 循环。

这个循环做的事很简单：调用模型，解析出工具调用，执行，把结果喂回去，再来一遍，直到模型自己说"干完了"。

就这么一套机制，把"会聊天的 AI"变成了"能干活的 Agent（智能体）"。

我最初也以为，等下一个更强的模型出来，Agent 自然就能用了。后来发现不是。同一个模型，放进聊天框就是聊天机器人，放进这个循环就是 Agent。

**Agent 和聊天机器人的分界线，不在智商，而在有没有"调工具、看结果、再决定"的闭环。**

一旦有了这个闭环，你面对的就不再是一个对话产品，而是一种新的工作组织方式。

## 一、从"你问它答"到"它自己干活"，中间隔了什么？

先把三个经常被混着说的东西分开。

**单次问答**：你问，它答。输入靠你打字，输出靠你自己拿去用。它对世界没有任何动作能力，答错了它也不知道。判断下一步的，是人。

**工具调用**：也就是让模型能调用外部工具。它可以在回答里"按一次"外部工具，查数据库、调接口。但它什么时候调、调完之后怎么办，还是外面的程序说了算，要不要按按钮、按完怎么办，仍然是人在判断。

**Agent 工作流**：模型进了循环。它调工具、看返回结果、根据结果决定下一步，一轮一轮推进，直到它判断任务完成。从已有的技术拆解来看，Claude Code 的引擎层干的就是这件事：约四十个工具挂在同一个循环上，而且每次执行前都先查权限，先问"能不能做"，再做。判断下一步的，第一次变成了机器。

三层的差别不是能力大小，而是谁在承担"接下来怎么办"的判断。

**Agent 接管的不是打字，而是流程。**

## 二、拆一个能干活的 Agent，里面到底有什么？

我第一次真正理解 Agent，是发现给 AI 布置任务和带一个刚加入团队的新同事很像：你告诉它目标，它自己拆任务、调用工具、推进执行，最后把结果交回来。

交代不清目标，它就自由发挥；不给上下文，它就瞎猜；没人验收，它就"看起来做完了"；不要求汇报，长任务一定跑偏。

把"它"换成"他"，这就是你给一个新员工安排工作时要交代的全部东西。

拆开一个真正能用的 Agent，里面一般有七样东西：

- **目标**：要做成什么，做到什么程度算完；
- **上下文**：这一轮它该看到哪些信息；
- **工具**：它被允许动什么，读文件、跑命令、查资料；
- **记忆**：跨轮次该记住什么，不该忘什么；
- **执行**：动手干活的那个循环本身；
- **验证**：干完之后，谁来检查是不是真的完成了；
- **交接**：做了什么、没做什么、卡在哪里，如何把情况交代给下一环。

而这套"给目标、调工具、看结果、再决策"的循环机制，在 Agent 工程里通常被称为 Harness。它不是某个神秘组件，也不是某个特定框架，更多是一套把模型组织起来做事的方法。

换句话说，Agent 工作流描述的是"它在做什么"，Harness 描述的是"它怎么被组织起来做"，一个讲行为，一个讲架构。

**Agent 的构成清单，读起来不像技术文档，更像一份岗位说明书。**

## 三、你真正要操心的，不是模型够不够聪明

一旦承认 Agent 是个"岗位"而不是个"功能"，问题就被重新定义了。

你让它改一个项目、查一个 bug、整理一份竞品分析。它不是答一句话，而是连续读文件、跑命令、改代码、生成结论。问题也从"它答得准不准"，变成"它有没有把事情带偏"。

而且这件事正在变得普遍。过去普通人接触 AI，主要是在聊天框里问问题。现在越来越多产品开始把模型塞进文件系统、浏览器、IDE、企业流程和自动化工具里。Agent 不再只是开发者玩具，而是会进入每个人工作界面的默认形态。

我最初的问题也是"该用哪个模型"。后来才发现这个问题本身问错了。

你不再问：这个模型能不能写代码？

你要问的是：谁来派活？谁来实现？谁来验证？谁来同步上下文？谁来评估它能不能胜任？谁来定义"完成"？出了错，谁负责？

这些问题没有一个是模型参数能回答的，因为它们问的不是"够不够聪明"，而是"谁来管、管什么、管到哪一步"。

它们是组织设计问题，过去发生在会议室里，现在发生在你的终端里。

Agent 把执行的链条拉长了，但链条的两端，起点和终点，仍然在人的手里。

也因此，**每一个 Agent 都需要一个人：不是需要人替它按回车，而是需要有人定目标、判结果、管边界、担责任。** 这就是为什么大部分 Agent 仍然会在关键动作前让你点一次确认，除非你主动打开一键跳过所有确认的 YOLO 模式，把判断权也一并交出去。

这篇文章不是在给 Agent 下定义，而是在换一个看法。真正的变化不是模型突然变聪明，而是工作方式变了，给一个目标，做一步，看一眼，再往前推进。不靠灵光一现，靠持续的小步修正，把事情做扎实。

聊天框时代，你主要是把问题问清楚。

Agent 时代，你更像是在把事情交代清楚，中间看看进展，最后对一下结果。

工具会换，模型会升级，但有一件事不会变：

**聊天机器人会等你提问，而 Agent 在等你管理。**
